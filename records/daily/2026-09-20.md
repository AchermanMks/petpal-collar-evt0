- 提速实测（同一块板、同一条 USB 线、Mac 本机桥）：

| 版本 | 每帧耗时 | 备注 |
|---|---|---|
| evt0.0.4：每帧重新上电+识别，1 KB 十六进制一问一答，Lua adler32 | 8.7～10.0 s | App 的 10 s 无新帧保护会反复触发 |
| evt0.0.5：传感器保持打开 + 16 KB 二进制窗口 + 预取，仍用 Lua adler32 | 1.43 s | 瓶颈是 Lua 逐字节 adler32（≈1.3 s/75 KB） |
| evt0.0.5 + `camera config sum=crc32`（底层 C 实现，桥默认） | **0.13 s（p50）/ 6.9 fps** | 300 帧 soak：299 成功、299 张互不相同、窗口未因丢包缩小；1 次 `camera_capture_failed` 自动重开传感器恢复（3.4 s 空档） |

- 经 HTTP 桥顺序取帧 20 s：6.74 fps、135/135 帧互不相同、期间 snapshot ≤0.10 s；空闲 4 s 后单次请求 0.22 s 拿到新帧；传感器断电后首帧 0.75 s。
- 桥：所有命令共用一个串口句柄（同一 tty 开两个句柄会互相抢字节）；只发“请求到达前 0.5 s 之后拍到、且未发过”的帧；请求停止 2 s 后停止取帧，固件再空闲 6 s 后传感器断电。检测到 r2 旧固件自动回退旧协议。
- 新工具：`tools/camera_soak.py`。测试：`tools/test_camera.py` 4 → 10 项。

## 已知问题 / 注意
- 板子从 Win11 换插到 Mac 后不会自动枚举，**必须按一次 `reset`**（今天 4 次都如此）；真断电后要长按 `PWRKEY`。
- 电池 ADC0 读数在 3014～3680 mV 间跳，模组 VBAT 3989 mV；出现过 `lastReson 0 0 5` 自发重启 → 与 F 线“电池路径压降”一致，联调时 USB 保持插着。
- Python urllib 会走 Mac 系统代理（SkyVPN），访问 127.0.0.1 桥要禁用代理；curl 不受影响。
- Mac 上 `Downloads/petpal_parallel_bundle` 不完整（.soc 为 0 字节），不要用。
- excamera.lua 有一处本地改动：`photo()` 增加可选 quality 参数。
- 以上均为 USB 台架（Mac 本机 127.0.0.1）；不是 4G 远程直播。
